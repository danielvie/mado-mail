# ADR 0003: Add local macOS support

The operator expanded Mado Mail's personal-use scope to macOS. This supersedes only the Windows-only restriction in ADR 0001; Rust, GPUI, the triage workflow, and existing Windows behavior remain. Linux, signed app bundles, notarization, and distribution installers remain outside scope. See [the specification](../../SPEC-macos-support.md).

Keep GPUI and Wry, selecting WKWebView on macOS and WebView2 on Windows. Target-specific dependencies isolate Windows APIs and resources. With default features disabled, macOS must explicitly enable `gpui_platform/font-kit`; otherwise GPUI selects NoopTextSystem and renders controls without any text. macOS uses a native titlebar, system font, Command editing/application shortcuts, and HOME-based settings at `~/.mado/mado-mail`. The existing keyring dependency selects macOS Keychain; credentials are never stored in plaintext settings.

Enable the pinned GPUI platform's `runtime_shaders` feature only on macOS. A separate build-time Metal toolchain was unavailable on the development host, and Xcode's component downloader failed because its DVTDownloads framework was missing. Runtime shaders avoid modifying the host's Xcode configuration, at the cost of compiling shaders at startup. No startup-performance improvement is claimed.

Wry's macOS API lacks WebView2's general HTTP(S) subresource interceptor. A CSP-only port would drop native request protection, so `reader_macos.rs` compiles WKContentRuleList policies before creating/loading the reader. Sanitization and CSP remain in place. Policy preparation failure leaves the reader disabled. Native rules block resources by default, allowing only the internal document and approved raster data images. Explicit opt-in permits HTTPS image resources and blocks cookies. macOS starts with remote images blocked; Windows retains its existing enabled-by-default behavior. Opt-in can disclose opens and IP addresses, and blocking cannot undo requests already sent.

macOS cancels external navigation rather than opening the system browser because Wry's callback does not provide trusted user-initiation metadata. Popups, downloads, and permission requests are denied. A local native event monitor routes reader escape/image/application shortcuts back to GPUI without holding entity borrows during dispatch. The monitor is removed when the reader is dropped.

`task reader-check` uses a temporary HOME and synthetic mail. A synthetic-only custom-scheme raster fixture makes opt-in checks deterministic without network access. Production CSP/native policies cannot include that fixture allowance. The check also switches native rules independently of CSP to demonstrate native blocking. It covers native font availability and glyph metrics, visibility, resizing, synthetic native keys, Command editing, detached-reader independence, and stale completions. Native focus returns to GPUI after key dispatch, since dispatch can synchronously render and temporarily focus the browser body. Isolated startup checks use `scripts/check-macos-startup.py` for both run and demo.

Apple Silicon macOS checks passed, but the synthetic fixture does not verify live HTTPS requests, redirects, or exact WebView2 parity. Physical keyboard traversal, visual alignment, native control usability, real Gmail/Keychain authorization, Intel macOS, and Windows runtime regression checks require operator verification. Existing Windows checks remain available on Windows; unavailable checks are not counted as passing.
